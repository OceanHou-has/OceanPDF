# 前端界面改造说明（Home.vue）

本文基于 Vercel Web Interface Guidelines 的交互与可访问性规则，对当前 [Home.vue](file:///e:/my_project/oceanpdf2.0/ocean-pdf2.0/frontend/src/renderer/views/Home.vue) 做一次“可落地”的界面改造方案梳理，用于我们后续逐项讨论与实施。

参考规范（原文）：https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md

---

## 1. 背景与目标

当前 Home 页是“应用壳（侧边栏 + 顶部栏）+ 内容区（上传/已解析）”的结构，功能已基本可用，但在一致性、可访问性、响应式、以及交互明确性上存在明显短板，导致观感“偏硬、偏杂”，且存在键盘不可用等问题。

改造目标（按优先级）：

1. 可访问性与交互正确性优先：所有可交互区域键盘可达、可操作，焦点可见，语义正确。
2. 信息架构更清晰：导航、当前所在位置、主操作区（Upload/Parsed）层级明确。
3. 视觉系统统一：颜色、字体、间距、圆角、阴影形成可复用的“设计 token”，减少散落的硬编码。
4. 响应式更合理：窄屏下不再强制占 200px 侧栏，提供折叠/抽屉式导航。

---

## 2. 现状问题清单（按 file:line）

以下为面向“规范 + 体验”的问题定位，格式尽量贴近 `file:line`，便于后续逐条改。

- Home.vue:13-37 侧边栏导航项使用 `div` + `@click`，缺少键盘操作与语义（应使用 `button`/`a`，或补齐 `role/tabindex/keydown`）。
- Home.vue:13-37 导航项只有 hover/active 视觉，没有 `:focus-visible` 焦点态，键盘用户无法判断当前位置。
- Home.vue:29-36 “任务列表/设置”呈现为可点样式但没有点击逻辑（典型“dead zone”，看起来能点但点不了）。
- Home.vue:9 与 Home.vue:49-50 同时存在侧边栏 `h1`（OceanPDF）与内容区 `h2`（页面标题），页面标题层级不够清晰（建议让“当前页面标题”成为 `h1`，品牌名降级为普通文本或 `div`）。
- Home.vue:53-56 “并行度”与输入控件没有显式的可访问性关联（可见标签不是可访问标签；建议用 `label for` / `aria-label` / `el-form-item`）。
- Home.vue:147-152 使用 `height: 100vh` + `overflow: hidden` 作为全局布局容器，在移动端/小窗模式/系统缩放时容易产生“内容被裁切且不可滚动”的问题。
- Home.vue:186-195 `.nav-item` 使用 `transition: all 0.3s`，会带来不可控的性能与意外动画（规范建议只 transition 明确的属性）。
- Home.vue:157-158 大面积深色渐变背景可能出现 banding/对比度与氛围不稳定问题，且与 Element Plus 默认浅色系控件存在风格割裂。
- Home.vue:274-282 顶部按钮样式依赖 `.el-button` 选择器，但实际使用的是自定义 `Button1`，样式命中不确定，导致跨视图一致性风险。

## 3. 改造方向（推荐的“应用壳”形态）

### 3.1 信息架构：从“局部状态切换”升级为“可深链路的页面状态”

当前 `currentView` 只存在于组件内部，无法：

- 刷新后保持所在视图
- 支持浏览器后退/前进
- 支持分享链接定位到“已解析PDF”

规范倾向“URL 作为状态”。推荐方案：

- 把 Upload / Parsed 变成真正的路由（例如 `/` 与 `/parsed`，或 `/home?tab=upload|parsed`）。
- 侧边栏使用路由高亮（`aria-current="page"`）而非手工 class。

收益：

- 导航语义更正确（链接就是链接）
- 状态可持久化、可分享
- 以后“任务列表/设置”自然扩展为路由页面，避免死入口

### 3.2 视觉系统：先统一“基础规则”，再谈“更好看”

目前样式更像“单页 demo 视觉堆叠”，缺少系统性。建议先建立最小设计系统（不需要引入新库）：

- 颜色：背景/文本/边框/主色/成功警告等，统一成 CSS 变量（token）
- 间距：使用 4/8/12/16/24/32 的 spacing scale，减少随意 padding
- 圆角：统一 8/10/12（不要同屏出现过多不同半径）
- 阴影：统一 2-3 档（低、中、高）
- 字体：标题/正文/说明三档字号与字重

风格建议（更贴合论文工具的“专业感”）：

- 主体使用浅色中性底（例如 #f6f7fb），内容区使用白色卡片承载
- 侧边栏改为“轻深色/中性深灰”或“浅色侧栏”，避免高饱和渐变抢主内容
- 强调色用于“主操作/当前状态”，不要在背景上大面积使用

## 4. 页面结构改造建议（组件层面）

### 4.1 侧边栏（导航）

现状：`div.nav-item` 模拟按钮/链接。

建议（优先级从高到低）：

1. 用原生 `button`/`a` 替代可点击 `div`（最省心、最符合语义）。
2. 如果必须保留 `div`，至少补齐：`role="button" tabindex="0"` 与 `@keydown.enter/@keydown.space`。
3. 为当前页面添加 `aria-current="page"`，并确保键盘焦点态可见（`:focus-visible`）。
4. 把“任务列表/设置”在未实现前做成禁用态（视觉上明确不可用）或先移除入口。

交互细节：

- 命中区域最小尺寸：移动端至少 44px 高（桌面端至少 32px-40px，建议 44px 统一）。
- 避免“只有文字可点、图标不可点”的死区，整行应可点。

### 4.2 顶部栏（页面标题 + 动作区）

建议将顶部栏固定为一致结构：

- 左侧：当前页面 `h1` + 二级说明（可选）
- 右侧：动作区（主动作放最右，次动作靠左）

并行度控件建议改为标准表单语义：

- 用 `label` 关联输入，或用 `el-form` / `el-form-item` 让可访问标签自动生成
- 为并行度提供短解释（例如 tooltip 或帮助文本）：并行度越大速度越快但更吃 CPU/RAM

刷新按钮建议：

- 显示 loading 状态（请求期间禁用 + spinner），避免重复点击导致并发请求
- 保留原始文案，不要只剩 spinner

### 4.3 内容区（Upload / Parsed）

建议将内容区变为“可滚动容器”，避免全局 overflow hidden：

- 页面外壳（sidebar + main）可以满高
- 内容区允许滚动（尤其 ParsedList 可能很长）

同时建议统一“空/加载/错误”的占位规范：

- 空：告诉用户下一步能做什么（上传入口/刷新入口）
- 加载：骨架屏或轻量 loading（避免闪烁）
- 错误：可重试 + 明确错误原因（网络、后端未启动、文件不可读等）

## 5. 样式改造建议（可直接落地的规则）

### 5.1 统一 token（建议直接放在全局样式中）

建议先定义一组 CSS 变量（示例命名）：

- `--app-bg`, `--surface`, `--text-1`, `--text-2`, `--border`
- `--primary`, `--primary-weak`
- `--radius-sm/md/lg`
- `--shadow-sm/md`
- `--space-1..6`

Home.vue 内尽量只使用变量，不再散落硬编码色值。

### 5.2 动画与状态

- 禁止 `transition: all`，只对 `background-color`, `color`, `box-shadow`, `transform` 做 transition
- 所有可交互元素必须有 `:hover` 与 `:focus-visible`
- 支持 `prefers-reduced-motion`（减少动画/禁用位移动画）

## 6. 响应式方案（推荐）

### 桌面端

- 侧边栏固定宽度（例如 240px）+ 内容区自适应
- 顶部栏固定高度（例如 64-72px）

### 平板/小窗（<= 1024）

- 侧边栏支持“折叠态”（只显示图标），hover/展开提示文字
- 顶部栏保留标题，动作区收纳到更多菜单

### 手机（<= 768）

- 侧边栏改为抽屉（drawer）或顶部汉堡按钮打开
- 避免一直占 200px 导致内容区过窄

## 7. 实施路径（分阶段，便于回归）

### Phase 1：先把“交互正确”做完（强烈建议先做）

- 把侧边栏所有可交互项改成语义正确的 `button/a`
- 补齐键盘操作与焦点态
- 移除/禁用未实现入口，避免误导

验收：不使用鼠标也能完成 Upload/Parsed 切换 + 刷新 + 帮助。

### Phase 2：让“导航与状态”更可维护

- Upload/Parsed 迁移到路由（URL 作为状态）
- 侧边栏高亮与标题来源统一（由路由 meta 或统一映射）

验收：刷新页面仍保持在正确视图；浏览器后退/前进符合预期。

### Phase 3：引入 token，统一视觉

- 抽离基础变量到全局
- Home.vue 替换硬编码色值/阴影/圆角/间距
- 统一按钮/表单外观，减少“自定义组件 vs Element Plus”割裂

验收：同类元素（按钮、列表项、标题）跨视图一致。

### Phase 4：响应式与细节打磨

- 侧边栏折叠/抽屉
- 动作区收纳（更多菜单）
- 空/加载/错误态统一

---

## 8. 建议的验收标准（Checklist）

- 所有看起来能点的东西都能点；不能点的明确不可用
- 键盘可达：Tab 顺序合理，Enter/Space 可触发导航与按钮
- 焦点可见：`:focus-visible` 清晰、不被样式覆盖
- 可访问名称完整：图标按钮、输入控件均有可访问标签
- 不使用 `transition: all`
- 小屏可用：<= 768 时内容不被侧栏挤压，主要流程可完成
